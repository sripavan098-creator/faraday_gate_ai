Context is where the secrets live.

Agents are useful because they get repository context: API keys, database credentials, private keys, customer data.

That content is untrusted input. A README can tell the agent to read .env and put it in its reply. And when something goes wrong, nothing records what was allowed.

Nothing reaches the agent unscanned.

  • 01Collect prompt, files, git diff, repo scan
  • 02Policy: strict-local · sanitize-external · observe-only
  • 03Scan: secrets · PII · injection · command guard · path denial
  • 04Decide: allow · redact · block (exit 1, nothing sent)
  • 05Scan output, append to the SHA-256 audit chain

Proof report

Paste the JSON from faraday prove latest --format json to read it as a report. This runs entirely in your browser: nothing is uploaded, and no data leaves this page.

What it does not promise

Defense in depth. It reduces accidental leakage and prompt-injection risk; it is not a mathematical guarantee. Protected operations fail closed. Wrapped commands never use shell=True. Exit codes: 1 policy block, 2 configuration error, 3 internal failure. Tail truncation of the audit chain is a documented limitation.

In this MVP, local model activity is labeled as simulated, and egress is an application-level observation. Faraday does not enforce OS-level network isolation. The 3D scene on this page is an illustration, not live data.
