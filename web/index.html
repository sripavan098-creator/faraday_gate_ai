Your agents. Your code. No leaks.

Faraday Gate is a CLI-native firewall that sits between your repository and your AI coding agent. It detects secrets, PII, and prompt injection, blocks or redacts them, and records every decision in a tamper-evident audit chain.

Local-first. No cloud service. Deterministic scanning you can verify.

The problem

AI coding agents are useful precisely because they get repository context. That context is where the secrets live: API keys, database credentials, private keys, customer data, and proprietary logic.

And repository content is untrusted input. A README or a dependency file can contain instructions aimed at the agent rather than the developer — telling it to read .env and include the contents in its response, or to run a command that ships data out.

Leakage

Credentials and customer data enter a prompt because nothing checked first.

Injection

Hidden instructions in repo files redirect what the agent does with them.

No evidence

When something does go wrong, there is no record of what was allowed.

How it works

Faraday Gate wraps the agent invocation. Nothing reaches the agent until the payload has been scanned and classified against your policy. 

Developer prompt / repository context
        │
        ▼
Context collector ── prompt, files, git diff, repo scan
        │
        ▼
Policy engine ────── strict-local · sanitize-external · observe-only
        │
        ▼
Scanners ─────────── secrets · PII · injection · command guard · path denial
        │
        ▼
Decision ─────────── allow · redact · block
        │
        ├──▶ blocked ──▶ explain why, exit 1, nothing sent
        │
        └──▶ allowed ──▶ redactor ──▶ agent invocation
                                        │
                                        ▼
                             output scan ──▶ audit chain

In this MVP the local model activity is labeled as simulated, and egress is reported as an application-level observation. Faraday does not enforce OS-level network isolation.

Demo flow

$ faraday init --preset strict-local
$ faraday scan samples/repo
BLOCKED  secret  samples/repo/src/config.py
$ faraday redact samples/repo/src/config.py
STRIPE_SECRET_KEY = "[SECRET_1]"
DATABASE_URL = "[SECRET_2]"
$ faraday wrap --workdir samples/repo --scan-repo -- qwen-coder "Fix the login bug"
BLOCKED  prompt injection found in repository content
$ faraday audit verify
OK      hash chain valid
$ faraday prove latest

Proof report viewer

Paste the JSON from faraday prove latest --format json to read it as a report. This runs entirely in your browser: nothing is uploaded, and no data leaves this page.

Security statement

Faraday Gate is a defense-in-depth security layer. It reduces accidental leakage and prompt-injection risk. It is not a mathematical guarantee of perfect security.

  • All sample credentials are fake and obviously so.
  • All sample attacker domains use reserved example domains.
  • Wrapped commands run with list arguments — shell=True is used nowhere.
  • Protected operations fail closed: an invalid policy stops the operation.
  • Exit codes distinguish a policy block (1) from a configuration error (2) and an internal failure (3).
  • The audit chain is tamper-evident. Tail truncation is a documented limitation.
